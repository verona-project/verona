#+title: Verona compiler diagnostic codes
#+options: toc:2

* Reading a diagnostic

The =verona= compiler reports diagnostics on standard error. Each diagnostic
starts with =severity[code]:= after any source prefix. Source locations use
=path:line:column:= with one-based lines and byte columns. Evaluator call-frame
notes include their locations after the function name.

#+begin_example
input.vrn:2:34: error[type-mismatch]: type mismatch: expected i64, actual bool
input.vrn:1:25: note[expected-type-origin]: expected type established here
#+end_example

Codes are stable lowercase strings. A code identifies a diagnostic kind even
when its message changes. Related notes follow the primary diagnostic.
LLVM or native tool details can continue on subsequent lines under the Verona
diagnostic that introduced them. Warnings and notes alone do not cause failure.

This catalog covers diagnostics emitted by =verona=, including errors while
using its evaluator. Programs emitted by Verona have their own runtime output.

* Commands

All commands can report command-line, target configuration, and compiler
storage errors.

| Command | Additional diagnostic sources |
|---------+-------------------------------|
| =read= | File I/O and source reader. |
| =check= | Module collection, source reader, macro expansion, and semantic checking. |
| =eval= | The checks above and evaluator errors with call-frame notes. |
| =emit-llvm= | The checks above, lowering, and LLVM verification. |
| =optimization-report= | The checks above, lowering, LLVM verification, and optimization notes. |
| =compile= | The checks above, lowering, LLVM verification, native compilation, and inlining notes. |
| =compile-report= | The executable compilation pipeline and its diagnostics. |
| =build= | Manifest reading and validation, package resolution, directory creation, and compilation. |
