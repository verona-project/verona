#+TITLE: Eager and Short-Circuiting Boolean Operations
#+DATE: 2026-11-01
#+STARTUP: overview

* Base API
| Form                       | Evaluation                                    |
|----------------------------+-----------------------------------------------|
| (base:and TEST...)         | Eager conjunction                             |
| (base:or TEST...)          | Eager disjunction                             |
| (base:not TEST)            | Unary complement                              |
| (base:and-then TEST...)    | Stop at the first false operand               |
| (base:or-else TEST...)     | Stop at the first true operand                |

Every operand and result is bool. The variadic macros require at least one
operand, and not takes exactly one. Reached operands evaluate once from
left to right. Eager macros expand to calls to the binary boolean primitives
and evaluate every operand unless evaluation fails or terminates. Short-circuit
macros construct nested exhaustive boolean matches, and every operand is
statically checked, including runtime-skipped operands. A single operand
still undergoes boolean checking and yields its original value.

Base builds each expansion in its macro definition environment. The result
uses primitive names or boolean matches directly. The compile-time evaluator
keeps its own boolean forms.

* Compiler adoption
The command driver uses and-then for guarded argument access, or-else for
mode and option selection, and eager or for checks of already computed
validation results. Invalid commands still share the usage diagnostic.

The Verona core separately recognizes the five expanded boolean primitives.
The Base APIs are library definitions used when bootstrapping the compiler
implementation. Short-circuit expansion uses the reference compiler's
boolean match support.

* Validation
The core suite checks truth tables, strict types and arity, and eager failure
behavior in the evaluator and native builds. Base integration tests check
left-to-right evaluation using an observable trace, short-circuit skipping,
guarded pointer access, aliased imports, nested macros, and arity and type
errors. Native tests run at optimization levels 0 and 2.
